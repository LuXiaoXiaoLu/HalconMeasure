## Measure.Halcon.Demo —— 图像保存接口重构

**背景**：`FormMain.btn_SaveImage_Click` 原来用 `FileName.Substring(FileName.IndexOf('.')+1)` 取格式字符串，再连同 path 一起传给
`ImageHelper.SaveImage(string path, string format, HObject hImage)`。两个问题：
1. `IndexOf('.')` 取的是**全路径里第一个点**，路径含 `D:\my.folder\1.bmp` 这类带点目录时会截错。
2. 后缀大小写/别名原样透传（`.JPG`、`tif`），HALCON 只认 `bmp/png/jpeg/tiff`，会抛异常。

**改动**（编译已通过，`dotnet build` 0 警告 0 错误）：
- `Helper/ImageHelper.cs`
  - 补 `using System.IO;`（没有它 `Path.GetExtension` 不可用 —— 这是用户报"没有这个方法"的原因）。
  - `SaveImage` 改为**两参数** `SaveImage(string path, HObject hImage)`，格式在方法内部从 `Path.GetExtension(path)` 推导。
  - 新增静态字典 `SaveFormats`（OrdinalIgnoreCase）：`.jpg/.jpeg → jpeg`、`.tif/.tiff → tiff`、`.bmp → bmp`、`.png → png`；不支持的后缀返回失败结果，不再让 HALCON 抛异常。
  - 保存前 `Directory.CreateDirectory(Path.GetDirectoryName(path))` 兜底建目录。
- `FormMain.cs`
  - 调用点改为 `image.SaveImage(saveFileDialog.FileName, HImage)`。
  - Filter 改成标准 `"描述(*.ext)|*.ext"` 形式，Save 对话框补上 TIFF；`DefaultExt` 由 `".bmp"` 改为 `"bmp"`，并显式 `AddExtension = true`。

**环境备忘**：本机沙箱会拦截 `MSBuild.exe`（判定为 LOLBin），VS 18 Community 的 MSBuild 路径也存在但跑不起来；
**编译验证改用 `dotnet build`（.NET SDK 可正确构建 net48 旧式 csproj）→ 可用**。

**遗留待办**（用户未确认）：`tb_Gain` / `tb_ExposureTime` 是 WinForms `TrackBar`，高度受系统主题锁定，设计器改 Size.Height 无效，需套 Panel 容器才能撑高度。

## HALCON .NET 的 IDisposable 实况（反射实测，halcondotnet 25.11）

用临时 net48 控制台探针 + 反射查得：

| 类型 | 基类 | 实现 IDisposable |
|---|---|---|
| `HObject` | `HObjectBase` | ✅（还有 ISerializable、ICloneable） |
| `HImage` / `HRegion` | `HObject` | ✅（继承） |
| `HXLDCont` | `HXLD` | ✅ |
| `HWindow` | `HHandle` | ✅ |
| `HTuple` | `Object` | ✅（**反直觉**，确实有 `Dispose()`） |
| `HWindowControl` | `UserControl` | ✅（WinForms 控件都实现，但**不该手动 Dispose**，归 Form 管） |
| `HOperatorSet` | `Object` | ❌ 静态类 |

- `HObject` 有 `IsInitialized()` 和 `Dispose()`；**终结器 `Finalize` 声明在 `HObjectBase`** → 忘了 Dispose 时 GC 最终会回收非托管图像句柄，但时机不定，峰值内存会失控。
- **本项目实际泄漏点**：`ImageHelper.ReadImage` 里 `HOperatorSet.ReadImage(out hImage, imagePath)` 直接覆盖了 `FormMain.HImage` 字段，旧 HObject 引用丢失、永远 Dispose 不到。正确姿势：先读进局部 `newImage`，成功后再 Dispose 旧的，最后才赋给字段。
- **环境备忘补充**：沙箱拦截 `[Reflection.Assembly]::LoadFrom`（等同于 Add-Type）。查 .NET 类型元数据的可行替代方案 = **临时建 net48 SDK 风格 csproj + dotnet build + 直接跑 exe**。
