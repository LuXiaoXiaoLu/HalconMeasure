`DelegationConsole = {2EACA947-7F5F-4CFA-BA87-8F7FBEEFBE69}`、
`DelegationTerminal = {E12CFF52-A866-4C77-9A90-F570A7AA2C6B}`（不同）。
**写注册表 GUID 这类"看起来对就行"的值，必须查官方表，不能凭印象。**

另外确认了两个前置条件：Win10 需装过 KB5026435 才支持"默认终端应用程序"（本机满足）；
`HKCU\Console` 的 `ForceV2` 必须不是 0（本机为 1，正常）。

## HALCON 25.11 的 .NET API 实况（反射核对，重要）

起因：用户问"教程上有 `HOperatorSet.CloseAllFramegrabbers()`，为什么我这没有"。

**结论：不是配置问题，是 HALCON 版本差异 + 那个算子本来就不该在应用里用。**

用 net48 探针反射 `halcondotnet.dll`（25.11）得到的事实：

- `HOperatorSet` 共 **2242 个公开静态方法，全部 PascalCase**（小写开头的 0 个）。
  → 旧教程里那种 `HOperatorSet.open_framegrabber(...)` 小写写法在这一版**已不存在**，只有 `OpenFramegrabber(...)`。
- **没有 `CloseAllFramegrabbers`**。全部 `Close*` 算子只有单项关闭：`CloseFramegrabber`、`CloseWindow`、`CloseFile`、`CloseIoDevice`、`CloseSerial`、`CloseSocket`…一个 `CloseAll*` 都没有。
- `HFramegrabber : HHandle : HHandleBase`，**实现 IDisposable**（`Dispose` 声明在 `HHandleBase`）→ 可以 `using`。
  构造：`HFramegrabber(name, hRes, vRes, imgW, imgH, startRow, startCol, field, bitsPerChannel, colorSpace, generic, externalTrigger, cameraType, device, port, lineIn)`
  实例方法：`HImage GrabImage()`、`GrabImageAsync(double)`、`Void GrabImageStart(double)`、`Void CloseFramegrabber()`、`Void Dispose()`、`SetFramegrabberParam(string,string)`。

**官方文档查证（MVtec）**：`close_all_framegrabbers` 即使在 HALCON 12 里也写着
> is obsolete and is only provided for reasons of backward compatibility …
> **exists solely for the purpose of implementing the "reset program" functionality in HDevelop.**
> **must not be used in any application.**

演进：≤12 存在但禁用 → **19.11 起标为 "This operator is inoperable"**（名字还在，调用无效果）→ **25.11 从 .NET API 移除**。
所以老教程抄它进应用代码本身就是错的写法。

**新接口（25.11 里新旧并存，实测 11 个新算子都在）**：官方迁移表
`open_framegrabber`→`create_image_source`+`connect_image_source`；
`close_framegrabber`→`disconnect_image_source`；
`grab_image`→`snap_from_image_source`；`grab_image_async`→`fetch_from_image_source`；
`grab_image_start`→`start_image_source`；`get/set_framegrabber_param`→`get/set_image_source_param`（参数组改用 GenParam `'group'`）。

**句柄有效性判断 API（反射 + 运行实测）**：
- `HHandleBase`（所有 HALCON 句柄类的基类）提供 **`Boolean IsInitialized()`**、`Void InvalidateWithoutDispose()`、`IntPtr Handle`（可读写），`Dispose()` 也在这里。
- `HHandle` 提供 `Void ClearHandle()`、**`HTuple TupleIsValidHandle()`**（实例方法，返回 HTuple，可直接 `.I`）。
- **`HOperatorSet.TupleIsValidHandle` 的签名是 `static void TupleIsValidHandle(HTuple handle, out HTuple isValid)`** —— 返回 **void**，结果走 out 参数。写成 `...TupleIsValidHandle(h).I` 会编译报错（对 void 取成员）。我第一遍就写错了，被用户踩到。
- **HALCON .NET 的通用约定（重要，能解释大量"为什么这里没有返回值"）**：
  `HOperatorSet.Xxx(...)` 的所有**输出参数一律是 `out`，方法本身返回 `void`**；
  而 `HXxx` **类的实例方法**才把输出值当作返回值。
  例：`void HOperatorSet.GrabImage(out HObject image, HTuple acq)` ↔ `HImage HFramegrabber.GrabImage()`；
  `void HOperatorSet.OpenFramegrabber(..., out HTuple acqHandle)` ↔ `void HFramegrabber.OpenFramegrabber(...)`。
- **`TupleIsValidHandle` 的运行时行为实测（不可靠，别用它做守卫）**：
  `null` → `HTupleAccessException: Index out of range`；`new HTuple()` → 同样抛；
  `new HTuple(12345)` / `new HTuple("abc")` / `new HTuple(-1)` → `HOperatorException #1201: Wrong type of control parameter 1`。
  即**只接受真正的 HANDLE 类型元组**，普通/空元组会抛。
- **`HHandle` / `HFramegrabber` 类天生安全**（实测）：
  `new HHandle().IsInitialized()` = False、`new HHandle().TupleIsValidHandle().I` = 0、
  `new HFramegrabber().IsInitialized()` = False、`new HFramegrabber().Handle == IntPtr.Zero` = True，**都不抛异常**。
- **结论**：句柄状态判断一律走 **`HFramegrabber` 字段 + `IsInitialized()`**，不要用 `TupleIsValidHandle` 做守卫。
- `HTuple` 取值用属性：`.I`(Int32) / `.D`(Double) / `.S`(String) / `.L`(Int64) / `.H`(HHandle) / `.Length`(只读)；对 null 取 `.I` 会 `NullReferenceException`。
- `OpenFramegrabber` 用**局部 HTuple 接收**、成功后再赋给字段（out 参数会先被赋值，抛异常时会留下脏值）。
